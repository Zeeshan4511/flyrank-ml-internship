Abstract

This project explores a content-oriented decision-support problem: how a machine learning workflow can identify patterns in supplied participant data and turn those patterns into a ranked, human-reviewed action queue. Using the FlyRank ML Internship dataset, I evaluated whether demographic, lifestyle, family-history, and dietary features could classify supplied colorectal cancer risk categories. A Random Forest model was compared with a Logistic Regression baseline using the same 80/20 stratified train-test split, where Random Forest achieved measured accuracy of 90.5% and an F1-score of 57.8%, compared with 87.0% accuracy and a 40.9% F1-score for Logistic Regression. The Random Forest achieved 41.9% recall for the high-risk class, showing that some high-risk records were still missed. These results are treated as observed and directional evidence from this dataset and as a decision-support prototype rather than evidence of clinical accuracy or real-world generalisation.

1. Research Question & Case Study

The Content Problem

A practical challenge in content and decision-support workflows is deciding which records, topics, or signals deserve attention first. A model can help with this prioritisation by identifying measurable patterns in available data, but the output needs to remain understandable, reviewable, and appropriately limited.

FlyRank case-study framing

This project uses the supplied FlyRank ML Internship dataset as a practical case study for that workflow. Rather than treating a model score as a final decision, the project demonstrates how predictive signals can be evaluated and translated into a ranked queue for human review.

The workflow connects:

Data → Model → Validation → Ranked Action → Human Review

Research Question

Can demographic, lifestyle, family-history, and dietary features be used to classify whether a participant belongs to a low-risk or high-risk category, and can the resulting model output provide useful directional signals for human-reviewed prioritisation?

Decision Supported

The intended decision is prioritisation for human review.

The model can rank records according to their measured predicted risk and provide directional reason codes based on the available features. This can help a reviewer decide which records may deserve earlier attention.

The model output is therefore treated as a decision-support signal, not as a final decision.

Important: The model is not intended to diagnose colorectal cancer, predict a clinical outcome, replace professional judgement, or operate as an autonomous medical decision system.

3. Methodology

Model Selection

Random Forest was selected as the primary model because it can capture non-linear relationships between features and the target and provides feature-importance information for interpretation.

Logistic Regression was selected as the baseline because it is a relatively simple and commonly used classification method.

Features and Preprocessing

The model uses demographic, lifestyle, family-history, pre-existing-condition, and dietary features. Participant_ID and CRC_Risk were excluded from the feature matrix.

Categorical variables were converted to numerical representations before modelling. Missing pre-existing condition values were represented as None.

Validation Design

The main evaluation used an 80/20 stratified random train-test split with random_state=42.

  • 800 training records
  • 200 testing records

Stratification was used to maintain the target-class distribution between the training and testing sets.

A Week-6 validation audit also considered the question of whether a grouped or time-aware split would better support generalisation claims. Because the available dataset contains individual participant records and does not provide a true client identifier, repeated participant history, or a suitable time variable, the available evidence does not support a genuine client-level or time-aware generalisation claim.

Validation interpretation: The reported performance should therefore be understood as performance on the tested random split rather than evidence of reliable real-world generalisation.

Leakage Audit

The final feature set was reviewed for direct target leakage. CRC_Risk was excluded because it is the target. Participant_ID was excluded because it is an identifier rather than a meaningful predictive feature.

A stricter production-style pipeline would fit categorical preprocessing only on the training data. Therefore, the current implementation should be considered a research prototype rather than a production-ready clinical pipeline.

Random Forest produced higher measured performance than the Logistic Regression baseline across the reported metrics on this tested split.

The largest difference was observed in F1-score, increasing from 40.9% for Logistic Regression to 57.8% for Random Forest.

Important interpretation: The high-risk recall was 41.9%. Therefore, the model did not identify every high-risk record in the test set. Accuracy should not be interpreted by itself as evidence that the model is highly reliable.

5. Feature Interpretation

The Random Forest feature-importance analysis showed the following variables among the strongest measured contributors in the model:

  1. BMI
  2. Lifestyle
  3. Age
  4. Family History of CRC
  5. Vitamin A
  6. Vitamin C
  7. Proteins
  8. Carbohydrates
  9. Iron
  10. Fats

These feature-importance values describe how the Random Forest used the available variables during prediction.

Not causal evidence: A feature having high model importance does not mean that changing that feature would necessarily change colorectal cancer risk. The importance results are therefore treated as directional model observations rather than medical conclusions.

6. Limitations & Honest Framing

Dataset

The dataset contains a limited number of participant records and may not represent other populations.

Validation

The main evaluation uses a random participant-level split rather than true client-level or time-aware validation.

Model

High-risk recall was 41.9%, meaning that some high-risk records were missed.

Features

The model only has access to the variables provided in the dataset.

What This Work Cannot Claim

  • It cannot claim clinical validation.
  • It cannot claim to diagnose colorectal cancer.
  • It cannot claim reliable real-world generalisation.
  • It cannot claim that feature importance represents causation.
  • It cannot claim that model predictions replace professional judgement.

Supported Claim

On the tested dataset and random 80/20 split, Random Forest showed higher measured classification performance than the Logistic Regression baseline and can be used as a directional decision-support prototype for prioritising records for human review.

7. Ranked Recommendations

The action playbook converts model predictions into a ranked human-review queue. The recommendations are intended for research and decision-support use rather than automated production decisions.

01 — High Priority Review

Records with higher measured predicted risk should receive earlier human review.

Reason codes:
AGE_DIRECTIONAL_SIGNAL BMI_DIRECTIONAL_SIGNAL FAMILY_HISTORY_SIGNAL LIFESTYLE_SIGNAL

These codes describe available characteristics associated with the model's ranking. They are not causal explanations.

02 — Standard Review

Records with moderate predicted risk can be placed into the normal review queue.

A human reviewer should examine the complete available information before taking any action.

03 — No Immediate Model-Based Action

Lower predicted-risk records do not automatically require an intervention based on this model.

A low model prediction should never be interpreted as proof that a participant has no health risk.

Human Review Rules

  1. Check the available participant information.
  2. Check for missing or unusual values.
  3. Review the model prediction together with its reason codes.
  4. Consider relevant information that is not available to the model.
  5. Do not interpret the model prediction as a diagnosis.
  6. Record the final human decision separately from the model output.

What Should NOT Be Automated

  • Diagnosing colorectal cancer.
  • Automatically starting or stopping treatment.
  • Automatically referring a participant.
  • Automatically rejecting a participant.
  • Automatically communicating a medical diagnosis.
  • Making decisions based only on a single feature.
  • Treating model probability as confirmed medical probability.
  • Replacing qualified professional judgement.

8. Monitoring & Retraining

Model-based recommendations can become stale when the underlying data changes. The following signals should trigger a review.

  • Important feature distributions change substantially.
  • The percentage of high-risk predictions changes unexpectedly.
  • False-negative cases increase.
  • High-risk recall decreases on new evaluation data.
  • F1-score decreases meaningfully on independent evaluation data.
  • New categories or values appear that were not present during training.
  • Feature definitions or data-collection methods change.
Retraining principle: Retraining should not happen automatically after every small change. New data should first be checked for quality and relevance, and a candidate model should be compared with the existing model using a consistent evaluation process.

10. Conclusion

This project measured whether demographic, lifestyle, family-history, and dietary features could be used to classify the supplied colorectal cancer risk categories.

On the tested 80/20 stratified split, Random Forest achieved 90.5% accuracy and a 57.8% F1-score, compared with 87.0% accuracy and a 40.9% F1-score for Logistic Regression.

These results show an observed performance advantage for Random Forest on this dataset and split.

However, the 41.9% recall for the high-risk class and the limitations of the available validation design show why the result should be treated cautiously.

The final output is a research and decision-support prototype that ranks records for human review rather than an automated clinical system.
